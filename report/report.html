openpoke · main vs fork-architecture

OpenPoke agent architectures

The same reminder request, "set reminders for my 3 meds at 8am, 2pm and 8pm every day", traced through both versions. Highlighted parts are the hops the fork removes, or what replaces them.

What changed, by problem

§1 handoff

The server writes the handoff

delegate(name, task?, note?) replaces LLM-written instructions. The agent gets the user's words verbatim and can call read_conversation for anything older. When one message holds several tasks, or Poke acts on an agent's result, task names the agent's part, and the agent does only that.

§2 granularity

One goal, one agent

The prompt no longer asks Poke to split work. One agent issues all its tool calls together, and they run in parallel. Long logs are compacted into a task summary.

§3 sprawl

Search instead of a full list

Roster entries carry a summary and status. Poke searches for the owning agent before delegating (top 3, BM25), instead of seeing every agent ever created. Finished agents are archived and revived on demand.

Cases passing every run: original 21/22, fork 21/22. The fork fixed A2 (no extra, unrequested dentist reminders) and regressed on R6: in 2 of 3 runs its reminder said "call their sister" instead of "call Ana", because a name given 15 turns earlier stayed in Poke's history rather than the handoff.

In short: the fork does the same work with 23% fewer LLM calls, 20% less input, 22% less output, and a bounded agent list, with no loss in task completion, reply quality or latency.
